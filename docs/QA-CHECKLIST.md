# Navvi — QA 测试清单（v0.6 稳定性基线）

用途：每次 ChatGPT 改版、或本插件改完代码后，按此清单手工回归，确认 7 大类功能正常。
环境：最新版 ChatGPT web 端（https://chatgpt.com/c/... 长对话）。
原则：纯手工点测；不依赖自动化脚本。每项含「前置 / 操作 / 预期 / 通过标准」。

---

## 1. Timeline 渲染 & Hover Wave & Preview Card
- **前置**：打开一段含 ≥ 10 条用户 Prompt 的长对话。
- **操作**：
  1. 观察右侧 stripe rail 是否出现，默认灰色细条。
  2. 鼠标悬停某 stripe，观察其变粗 / 变长 / 变黑，附近 stripe 是否有波浪式轻微变化。
  3. Hover 时是否出现 Preview Card。
- **预期**：
  - Preview Card 第一行 = Prompt 时间戳；第二行 = Prompt 文本预览；第三行 = 附件信息（仅文件名/图片/视频/文件，不污染正文）；第四行 = Important / Favorite 两个图标。
- **通过标准**：rail 渲染正常、hover wave 可见、preview 四行内容齐全且准确。

## 2. Jump（近距离 + 长距离）
- **前置**：同上长对话，滚动到中部。
- **操作**：
  1. 点击靠近当前位置的 stripe → 观察是否跳转并高亮。
  2. 滚动到顶部，点击靠近底部的 stripe（长距离）→ 观察跳转。
- **预期**：即使跨虚拟滚动长距离，也能准确定位到目标 Prompt 并居中，无“跳错/跳不到”。
- **通过标准**：近距与远距点击均精确落位（允许 1 次校正后稳定）。

## 3. 时间戳 = 真实发送时间
- **前置**：对话中包含不同时间发送的 Prompt（可隔几分钟发几条）。
- **操作**：查看 Timeline / Preview Card 的时间戳。
- **预期**：显示的是该 Prompt **真实发送时间**，不是打开页面的时间。
- **通过标准**：时间戳与 ChatGPT 消息旁显示的时间一致（DOM 优先；新发送则用发送事件兜底）。

## 4. Search（prompt 内容 + 附件名）+ 高亮
- **前置**：对话中含可搜索关键词的 Prompt，以及带附件（图片/文件）的 Prompt。
- **操作**：
  1. 打开 Finder，搜索某 Prompt 正文关键词。
  2. 搜索某附件文件名。
- **预期**：结果列表仅显示匹配项；点击结果跳转原位置；匹配关键词有高亮。
- **通过标准**：正文搜索与附件名搜索均命中正确结果，点击可跳转。

## 5. Important 标记 + Important Only 视图
- **前置**：对话中若干 Prompt。
- **操作**：
  1. 对某 Prompt 标记 Important → 观察 stripe 是否出现黄色 side tick。
  2. 当前 active + important 时 stripe 是否变黑 + 黄 tick。
  3. Finder 切到 “Important only” → 列表是否只显示标记项。
- **通过标准**：标记/取消标记即时反映；Important only 视图过滤正确。

## 6. Favorites（增 / 删 / 复制 / tag 筛选 / 标题）
- **前置**：处于某对话。
- **操作**：
  1. 收藏一条 Prompt（填 title、tags）→ 在收藏夹查看。
  2. 复制收藏全文。
  3. 用 tag 筛选收藏。
  4. 删除一条收藏。
- **预期**：收藏保存全文 + title + tags；复制得到完整 prompt；tag 筛选生效；删除后列表更新。
- **通过标准**：增 / 删 / 复制 / 筛选全部正常，收藏为全局（跨对话可用）。

## 7. Storage 持久化（刷新后仍保留）
- **前置**：已标记若干 Important、收藏若干 Prompt。
- **操作**：刷新页面（或重新打开该对话）。
- **预期**：Important 标记与 Favorites 仍然存在（来自 chrome.storage.local）。
- **通过标准**：刷新后标记与收藏不丢失；且无任何上传/云同步行为（仅本地）。

## 附：改版自检（Drift Self-Check）验证
- **操作**：临时把所有选择器改乱码（仅测试用，改完还原），加载插件。
- **预期**：插件角落出现黄色「⚠ 当前 ChatGPT 版本可能不兼容，时间轴可能为空」提示，且 console 输出缺失选择器名。
- **通过标准**：能“早发现”选择器失效；若仅首选失效、候选仍命中，则功能正常（验证 fallback 生效）。

## 8. v0.7 AI Response Highlight（选中 AI 回复高亮）
- **前置**：打开一段含多条 AI 回复的长对话；确认右下角预览卡显示「UI v22」。
- **操作**：
  1. 在一条**已生成完成**的 AI 回复中拖选一段文字。
  2. 选区旁浮出工具条（5 色圆点 + 「想法…」备注框 + 取消）。
  3. 在备注框输入一句话，点击某个颜色圆点。
  4. 观察原文字是否出现背景 + 下划线 + 文字变色。
  5. 刷新页面（或重新打开该对话）。
  6. 点击 rail 下方第二个图标（高亮）打开 Highlights 面板，确认出现该条（片段 + 上下文 + 备注 + 可点跳回）。
  7. 在页面上点击已高亮的文字，浮出小卡片，改色 / 改备注 / 加标签 / 删除 / 跳回。
  8. 切到另一个对话，再打开 Highlights 面板，确认清单换成新对话的（或为空）。
  9. 在 AI **正在生成**时拖选文字并点颜色。
- **预期**：
  - 高亮视觉为「背景色 + 同色下划线 + 文字变色」三者皆有。
  - 刷新后高亮自动恢复（页面重新渲染后仍可见）。
  - Highlights 面板仅展示**当前对话**高亮；切对话即换清单。
  - 点击页面高亮 → 原地卡片可改色 / 备注 / tags / 跳回 / 删除。
  - 生成中高亮被拦截并提示「AI 正在生成，稍后再标」。
- **通过标准**：创建 / 恢复 / 面板跳回 / 原地编辑 / 切对话隔离 / 流式防标 全部正常；且高亮**只**作用于 AI 回复，选中用户自己的 Prompt 或输入框**不**弹工具条。
- **边界**：高亮跨段落（多 `<p>`）也能正确包住；禁止上传、不云同步、不影响 Timeline / Finder / Favorites 既有功能。
